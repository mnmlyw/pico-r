# Probes for known, oracle-confirmed gaps not yet fixed. One stem per line.
# Discovered by an automated corpus/spec-audit sweep; each probe+golden pair
# is real evidence of a divergence from official PICO-8, just not yet acted
# on. Remove a line once its engine fix lands and the probe matches.
# tostr-tostring-metamethod-ignored: the actual bug (tostring()/tostr()
# ignoring a table's __tostring metamethod) is fixed and 3 of the golden's
# 4 RESULT lines match byte-exact. The 4th (a plain table's default
# "table: 0xADDR" display) bakes in the OFFICIAL binary's own heap address
# from whenever the golden was captured -- that address can never be
# reproduced by any implementation running as a different process, so this
# probe can't fully graduate regardless of correctness. Left listed rather
# than fabricating a matching address.
tostr-tostring-metamethod-ignored
# shift-count-overflow-clamped-not-zeroed: shl/shr/lshr clamp the shift
# count to 31 via .min(31)/.clamp(0,31) before shifting, so a count >= 32
# lands on the same result as count == 31 instead of the fully-shifted-out
# value (0 for a left/logical shift, sign-extended 0/-1 for the arithmetic
# right shift). Also found in the same probe: shl(x, n) for n < 0 delegates
# to Rust's wrapping_shr (arithmetic, sign-preserving) but official PICO-8
# treats a negative shl count as a LOGICAL right shift (matches lshr, not
# shr) even for in-range counts -- shl(-1,-1) == lshr(-1,1) on real
# hardware, not shr(-1,1). Both are real, generalizable rules in
# src/pico_lua/api.rs's api_shl/api_shr/api_lshr, not probe-specific.
shift-count-overflow-clamped-not-zeroed
# split-nil-first-arg-no-error: api_split's arg_str(&a,0) falls back to an
# empty byte string when arg 0 is nil/omitted instead of raising a runtime
# error the way official PICO-8's split() does (a checklstring-style arg
# check) -- pico-r has an established Err(RtError::msg(...)) pattern used
# elsewhere in api.rs (setmetatable, rawset, cocreate) for exactly this.
# src/pico_lua/api.rs (api_split).
split-nil-first-arg-no-error
# tonum-hex-string-and-boolean-flag: three related divergences in api_tonum,
# all confirmed against the console. (1) A "0x...." string parses as a hex
# literal with NO flag -- tonum("0x0001.0000") is 1, pico-r returns nil.
# (2) Flag 0x1 means "read the digits as hexadecimal", so "12" -> 18 (pico-r
# agrees) but "0x0001.0000" is then not valid hex digits and yields 0, where
# pico-r returns 1 as if it had parsed the literal. (3) A BOOLEAN flag is
# IGNORED here -- tonum(s,true) == tonum(s) -- the OPPOSITE of tostr, where
# true means flag 1 (fixed; see tostr-flag-accepts-boolean). pico-r returns
# nil. Found while fixing tostr's boolean flag. src/pico_lua/api.rs (api_tonum).
tonum-hex-string-and-boolean-flag
